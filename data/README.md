# Data

This directory holds small, non-sensitive reference files used by the pipeline. Raw survey data, full network geometry, model artefacts, and large generated outputs are **not** committed to this repository.

## What's here

| File | Description |
|---|---|
| `category_keys.json` | Maps categorical attribute labels (e.g. `landuse`, `dilap_index`, `policy_era` class codes) to scholarly-ordered numeric scores, used in `04_sdi.ipynb` before MinMax scaling and weighting. |
| `model_scores.json` | Per-attribute model performance scores (Cramér's V for categorical, R² for continuous), generated by `02_model_train_evaluate.ipynb`, consumed by `04_sdi.ipynb` as weighting input. |

## What's not here, and why

| Excluded | Reason |
|---|---|
| `segments.geojson` (full network geometry + 35 centrality features) | Large file; derived from licensed/restricted Mappinest tileset data |
| `training_set.csv` (formal Tehran, surveyed attributes) | Contains real-world survey data not cleared for public redistribution |
| `prediction_set.csv` (periphery, unlabelled) | Same source restrictions as above |
| `models/`, `trained_models/` | Generated artefacts (PCA/scaler objects, MLP weights, label encoders); regenerate locally by running the notebooks in order |
| `evaluation_reports/` | Generated per-attribute evaluation output; regenerate via NB02 |

## Where the outputs live instead

The pipeline's final, public-facing outputs (aggregated to H3 hexagons — no segment-level or individually identifiable data) are hosted on Google Cloud Storage:

- `https://storage.googleapis.com/sdi-tehran-assets/data/outputs/hex.geojson`
- `https://storage.googleapis.com/sdi-tehran-assets/data/outputs/classification.json`
- `https://storage.googleapis.com/sdi-tehran-assets/data/category_keys.json`

These are what the live dashboard consumes, and what anyone reproducing only the aggregation/visualisation steps (rather than the full model pipeline) actually needs.

## Reproducing from scratch

If you have access to equivalent source data (your own segment-level centrality measures and surveyed attribute data for a comparable formal/informal urban split), place files matching the schemas below into this directory and update `config.py` paths if needed.

### `segments.geojson` schema
35 feature columns (CH/INT/NC/TD at 8 radii each, + angular connectivity, topological connectivity, segment length) + segment ID column + geometry.

### `training_set.csv` schema
Same 35 feature columns + segment ID + `mean_area`, `perimeter`, `landuse`, `mean_pop`, `dilap_index`, `policy_era`.

### `prediction_set.csv` schema
Same 35 feature columns + segment ID only (no labels).
